# Speekly — десктопный мессенджер

Electron (.exe для Windows) + Supabase (база данных, авторизация, Realtime и Storage).

## Структура проекта

- `src/` — интерфейс, клиентская логика, конфигурация и E2E-шифрование.
- `supabase/` — исходная SQL-схема и последовательные миграции.
- `tests/` — тесты криптографии.
- `build/` — ресурсы для сборки приложения.
- `.github/workflows/` — автоматическая сборка Windows установщика.
- `main.js`, `preload.js`, `package.json` — Electron и зависимости.

## 1. Настройка Supabase

1. Создай проект Supabase.
2. Для **новой пустой базы** выполни целиком `supabase/schema.sql`.
3. Если база уже создана по предыдущей версии схемы, не запускай базовую схему повторно: проверь состояние базы и применяй только отсутствующие миграции по порядку (`migration_2.sql`, `migration_3.sql`, `migration_4.sql`).
4. В Authentication → Providers → Email настрой подтверждение почты согласно выбранному сценарию регистрации.
5. В Project Settings → API возьми Project URL и публичный ключ (publishable key или legacy anon key) и укажи их в `src/config.js`.

Публичный ключ допустим в клиентском приложении. **Никогда не помещай service_role или secret key в клиентский код или GitHub.** Доступ к данным должен быть ограничен RLS-политиками.

## 2. Запуск

Требуется Node.js 20 или новее.

```bash
npm install
npm start
```

F12 открывает инструменты разработчика.

## 3. Тесты и сборка

```bash
npm test
npm run dist
```

Установщик Windows появится в `dist/`.

Для сборки через GitHub открой Actions → Build Windows exe → Run workflow. Установщик будет доступен в Artifacts. Сборка также запускается при публикации тега вида `v1.0.0`.

## Шифрование

Для E2E используется ECDH P-256, HKDF и AES-256-GCM через Web Crypto. Приватный ключ остаётся на устройстве; резервная копия хранится в Supabase в зашифрованном виде, защищённая паролем пользователя.

Сервер всё ещё видит метаданные переписки (участников, время и размеры сообщений/файлов). Профили и публичные медиа не шифруются. Сверяйте код безопасности с собеседником по независимому каналу.

**Важно:** до использования в реальной переписке требуется отдельный аудит реализации E2E, управления ключами, восстановления и RLS. Само наличие шифрования в коде не является независимым подтверждением его безопасности.
