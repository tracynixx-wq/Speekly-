# Speekly — десктопный мессенджер

Electron (.exe для Windows) + Supabase (база данных, авторизация, Realtime, Storage) + GitHub (код, сборка и обновления).

## Что есть (версия 1.3.1)

- Личные чаты в реальном времени без заявок в друзья: найди человека по нику в строке поиска «Чатов» и нажми «Написать». «В сети» и время захода, галочки прочтения, поиск по чатам.
- Блокировка пользователей: кнопка в профиле и в меню чата, список заблокированных в Настройки → Конфиденциальность. Блокировка проверяется базой (RLS), а не только интерфейсом.
- Фото, видео и файлы до 25 МБ, смайлы, просмотр фото, скачивание.
- Звонки 1 на 1: голос, видео, демонстрация экрана (WebRTC; сигналы шифруются ключом переписки).
- «Избранное» (заметки себе, хранятся только на этом компьютере) и «Система» (служебные уведомления).
- Стеклянный дизайн с обоями («Океан», «Закат», «Мята», «Гейминг»), режим «Классика», «Лёгкий режим», анимации.
- Профиль: обложка и аватар (в том числе анимированные), имя, о себе, несколько аккаунтов на одном компьютере.
- Настройки (все вкладки рабочие), русский и английский, «Помощь», статусы «В сети», «Не беспокоить», «Невидимка».
- Сквозное шифрование текста и файлов (см. ниже).
- Вход и регистрация только по нику и паролю. Почта пользователю не нужна.
- Обновления через GitHub Releases: приложение само проверяет новую версию и предлагает скачать её, без повторной полной установки.

## Структура проекта

- `src/` — интерфейс, клиентская логика, конфигурация и E2E-шифрование.
- `supabase/` — исходная SQL-схема и последовательные миграции.
- `tests/` — тесты криптографии.
- `build/` — иконки для сборки.
- `.github/workflows/` — автоматическая сборка Windows-установщика и публикация обновлений.
- `main.js`, `preload.js`, `package.json` — Electron, автообновление и зависимости.

## 1. Настройка Supabase

1. Создай проект Supabase.
2. **Новая пустая база:** выполни по порядку `schema.sql`, затем `migration_6_user_blocks.sql` (блокировки и личные сообщения без заявок) и, при необходимости, `migration_7_auto_confirm.sql`.
3. **База уже работает:** схему повторно не запускай. Примени только то, чего не хватает, по порядку: `migration_2.sql` … `migration_6_user_blocks.sql`. Версия 1.3.1 не требует новых таблиц; обязательна только `migration_6_user_blocks.sql`, если блокировки ещё не включены.
4. Подтверждение почты. Приложение превращает ник в внутренний адрес `ник@speekly.app`. Либо выключи **Confirm email** в Authentication → Providers → Email, либо выполни `migration_7_auto_confirm.sql`: она подтверждает такие аккаунты автоматически.
5. Миграция `migration_7_auto_confirm.sql` подтверждает только внутренние адреса `@speekly.app`; обычные email-аккаунты она не затрагивает. Если не хочешь менять поведение подтверждения в проекте, вместо миграции отключи Confirm email в Authentication → Providers → Email.
6. В Project Settings → API возьми Project URL и publishable key и впиши их в `src/config.js`.

Публичный ключ допустим в клиентском приложении. **Никогда не помещай service_role или secret key в клиентский код или GitHub.**

## 2. Запуск

Нужен Node.js 20+.

```bash
npm install
npm start
```

F12 открывает инструменты разработчика.

## 3. Тесты и сборка

```bash
npm test
npm run dist
```

Установщик появится в `dist/` (`Speekly-Setup.exe`).

## 4. Релизы и автообновление

Workflow `Build Windows exe` запускается при пуше в `main`, при теге `v*` и вручную. Он проверяет синтаксис, запускает тесты, собирает установщик и публикует в GitHub Releases файлы `Speekly-Setup.exe`, `latest.yml` и `.blockmap`. Приложение читает `latest.yml` из последнего релиза.

Чтобы выпустить обновление, увеличь `version` в `package.json` (например, до `1.3.2`) и запушь в `main`: тег `v1.3.2` и релиз создаются автоматически. Если пушишь тег вручную, он должен совпадать с версией в `package.json`.

Пользователь получает вопрос «Скачать обновление?», затем «Установить и перезапустить?». Журнал обновлений: `%APPDATA%\Speekly\updater.log`.

## Шифрование

Для E2E используется ECDH P-256, HKDF и AES-256-GCM через Web Crypto. Приватный ключ остаётся на устройстве; резервная копия хранится в Supabase в зашифрованном виде, защищённая паролем пользователя (PBKDF2). Код безопасности в шапке чата позволяет сверить ключи с собеседником по независимому каналу.

Сервер видит метаданные переписки (участников, время и размеры сообщений и файлов). Профили, аватары и обложки не шифруются. Собеседнику нужно хотя бы раз войти в обновлённое приложение, чтобы у него появился ключ.

**Важно:** до использования в реальной переписке нужен независимый аудит реализации E2E, управления ключами и RLS.
